# 심사 · 투표 · 발표 규칙 — 6일차 해커톤

과정 사이트의 '심사 · 발표 · 투표' 쪽과 같은 내용입니다. 보는 것은 화려함이 아니라 **한 장면이 운영 주소에서 끝까지 되는가**입니다.

## 심사 기준 넷 × 1–4점

| 기준 | 가중치 | 1점 | 2점 | 3점 | 4점 |
|---|---|---|---|---|---|
| ① 문제와 쓸모 | 30 | 기능 소개뿐 — 누구의 무슨 문제인지 흐리다 | 사용자나 불편 가운데 하나는 말했지만 시나리오와 이어지지 않는다 | 사용자 + 순간 + 불편을 한 문장으로 말하고, 시나리오가 그것을 푼다 | + 사용자의 말이나 전 · 후 숫자 하나(예: 30분 → 3분) |
| ② 동작하는 배포 | 30 | 운영 주소가 없거나 열리지 않는다(캡처만) | 운영 주소는 열리지만 시나리오가 끝까지 되지 않는다 | 시나리오 하나가 운영 주소에서 끝까지 된다 | + 시나리오 2개 이상 또는 제대로 된 저장 · AI, 그리고 390px에서 문제없음 |
| ③ 검증 · 안전 | 20 | 가상 표시가 없거나 실명 · 비밀이 보인다 | '(가상)' 표시는 있지만 SPEC의 확인 기준을 보여 주지 못한다 | SPEC의 확인 기준(Then)을 화면에서 보여 주고, '(가상)' · `doctor:secrets` PASS | + 사람 승인 · 되돌리기와 잘못된 입력 처리 |
| ④ 전달 | 20 | 3:10에 끊기거나 무엇을 만들었는지 전달되지 않는다 | 시연은 했지만 순서가 흐리거나 시간이 넘친다 | 문제 → 시연 → 어떻게 → 다음, 3:00 안 | + README만 보고 낯선 사람이 눌러 볼 수 있다 |

- 4점은 3점의 내용을 모두 채운 뒤 '+' 뒤의 것까지 해낸 경우입니다. 주제와 상관없이 같은 기준입니다.
- **총점 = Σ(점수 ÷ 4 × 가중치)**, 100점 만점. 심사위원 두 명의 평균. 동점이면 ② 평균 → ① 평균.
- 짝(2인)은 한 팀으로 한 번 채점합니다. 앱이 끝까지 안 돼도 백업 캡처로 발표하면 ① · ③ · ④는 그대로 채점합니다.

## 보스전 — 한 사람 3분

| 시간 | 할 말 | 화면 |
|---|---|---|
| 0:00–0:20 | 문제와 누구 | 첫 화면 |
| 0:20–2:10 | 시나리오 하나 끝까지 — Given · When · Then을 소리 내며 | 운영 주소 |
| 2:10–2:40 | AI가 한 일 / 내가 검증한 것 | README 또는 SPEC 한 줄 |
| 2:40–3:00 | 다음 단계 · 내 업무라면 | 다음 단계 한 줄 |

- 2:45 노란 신호 · 3:00 종 · 3:10 끊기. 질문은 받지 않습니다.
- 강사 노트북에서 내 운영 주소를 엽니다. 안 열리면 백업 캡처 3장, 그래도 안 되면 그 묶음의 끝으로.
- 다섯 명씩 네 묶음, 묶음 사이 1분은 방금 본 앱을 휴대폰으로 눌러 보는 시간입니다.
- 화면에 `.env` · 환경 변수 화면 · 비밀번호 · 실명 · 회사 실데이터를 띄우지 않습니다.

## 공감 투표

1. 16:00 전에 강사가 발표 순서대로 '번호 · 별명 · 앱 이름 · 링크'를 한 사람에 한 메시지씩 오픈채팅에 올립니다.
2. 17:15 '투표 시작' 뒤 마음에 드는 발표의 메시지 2개에 공감 — 내 것은 빼고(짝은 둘 다 우리 팀 메시지를 뺍니다).
3. 17:20 마감 — 강사가 메시지마다 공감 수를 셉니다.

## 시상

| 상 | 기준 |
|---|---|
| 대상 | 총점 1위 |
| 인기상 | 공감 수 1위(같으면 총점이 높은 쪽) |
| 쓸모상 | ① 문제와 쓸모 평균 최고 |
| 완성상 | ② 동작하는 배포 평균 최고 |

위 순서로 정하고, 한 사람(짝은 한 팀)에 하나만 줍니다. 점수표 원본과 순위표는 공개하지 않습니다.
