## 0. 늘 지킬 것

**AI에게 — 이 안내서를 쓰는 법**
- 프롬프트가 가리킨 절**만** 한다. `CLAUDE.md`의 '반드시' 9개(빌드 통과 · 비밀은 서버에만 · 한국어 화면 · 가상 데이터 · `db:push`만 …)가 모든 절에 함께 적용된다.
- 입력(`hackathon/` · `guide/` · `data/`의 원본)은 **읽기만** 한다. 수강생의 파일은 저장소 맨 위 `SPEC.md` · `README.md` · `DEMO.md`와 `app/` · `components/` · `lib/` · `data/`(새 파일) · `scripts/`(새 파일) · `prisma/`에 둔다.
- 파일을 여럿 바꾸는 일은 **계획을 먼저**(3–7줄: 바꿀 파일 · 만들 화면 · 확인 방법) 보여 주고, 승인받은 뒤 만든다.
- 숫자는 코드로 계산한 값만 쓴다. 모르면 '확인 필요'. 수강생이 말하지 않은 사실(사용자의 말 · 숫자 · 효과)은 지어내지 않는다 — 물어본다.
- 실명 · 실제 회사 · 실제 이메일(주소는 `@….example`만) · 전화번호 · 계좌 · API 키를 코드 · 데이터 · 커밋에 넣지 않는다. 메일 · 문자 · 알림을 실제로 보내지 않는다.
- AI 엔진(`claude -p`)을 부르는 스크립트는 `--dry-run`으로만 시험한다. 진짜 실행은 사람이 터미널에서 한다.
- 새 패키지 · API 키 · 외부 서비스 가입 · 바깥으로 나가는 발송이 필요하면 **만들기 전에 묻는다**(이름 · 이유 · 고정 버전 — `npm i 이름@버전 --save-exact`).
- 화면 규칙의 예외 하나 — 수강생이 지도를 고르면 OpenStreetMap 지도 그림(타일)만 `guide/design_rules.md` 6절의 '외부 이미지 금지' 밖으로 허용한다. 먼저 묻고(`leaflet@1.9.4` · npm으로, CDN 아님), 지도 아래 '© OpenStreetMap contributors'를 남기고, 핀은 그림 파일 없이 원(`circleMarker`)으로 · 가상 좌표만 찍는다.
- 커밋 · push 전에 파일 목록 · 두 줄 메시지(`6일차: 무엇` / 빈 줄 / `왜: 이유`) · 브랜치를 먼저 보여 준다. 오늘은 `main`에서 일한다 — **push = 운영 주소 배포**.
- 끝에는 그 절의 **'확인할 것 3줄'**을 보여 준다. 수강생은 그 3줄로 자기 화면을 확인한다.

**MVP 규칙 — 오늘 만드는 크기**(넘으면 만들기 전에 「1」의 '자르는 법'으로 줄인 안을 먼저 보여 준다)
- 한 사람 · 한 순간 · 한 동작 — 누가 · 언제 여는지 하나, 그때 하는 동작 하나
- 화면 3개 이하 · 쓰기 동작(저장 · 바꾸기) 1개 이하 · 로그인 없음
- 가상 데이터만, 200줄 이하 · 바깥 API는 키 없는 것만 · 앱 안에서 AI 부르기는 기본 끔
- 세이브 포인트 1(10:50)까지 운영 주소에 뼈대가 떠 있어야 한다

## 1. SPEC 인터뷰

**질문 5개 — 한 번에 묻는다.** `hackathon/00_idea_card.md`(수강생이 채운 카드)를 읽고, 아래 다섯 질문을 번호를 붙여 **한 번에** 묻는다. 질문마다 카드에서 짐작한 예시 답을 한 줄 붙인다(카드가 비어 있으면 예시 없이). 답을 받기 전에는 파일을 만들지 않는다.

1. 누가 · 언제 이 앱을 여나(직무 · 상황 하나)
2. 지금은 어떻게 하고, 무엇이 불편한가 — 숫자 하나(시간 · 횟수 · 실수)
3. 이 앱에서 하는 **단 하나의 동작**
4. 화면에 보이는 데이터 — 무엇을 몇 줄(가상)
5. 성공의 순간 — 3분 발표에서 보여 줄 한 장면

**쓰는 법** — 수강생의 답으로 `hackathon/01_SPEC_template.md`의 틀 그대로 저장소 맨 위 `SPEC.md`를 쓴다(새 파일 · 60–90줄).
- 시나리오 3–5개, 각각 **Given–When–Then** 세 줄. 시나리오 1 = 발표 장면.
- '하지 않을 것'은 3개 이상(예: 로그인 · 실제 발송 · 결제 · 실데이터).
- 답에 없는 칸은 지어내지 말고 `(확인 필요)`로 둔다. MVP 규칙을 넘으면 '자르는 법'대로 줄이고, 뺀 것은 '다음 단계'에 옮겨 적는다.
- 끝나면 보여 줄 것: 화면 목록 · 시나리오 1의 세 줄 · 하지 않을 것.

**자르는 법** — 장면 하나만 남긴다.
- 시나리오 1과, 그것에 꼭 필요한 화면 · 데이터만 남긴다. 나머지는 지우지 말고 `SPEC.md`의 '다음 단계'로 옮긴다.
- 쓰기 동작은 하나로 · DB는 저장이 핵심일 때만 · 로그인 · 발송 · 외부 연동 · 결제는 '다음 단계'.
- `h-cut`으로 불렸으면 **고치지 말고** 줄인 안만 표(지금 → 줄인 안 · 뺀 것 → 다음 단계)로 보여 준다.

## 2. 프로젝트 규칙

`hackathon/02_CLAUDE_project.md`의 틀로 `CLAUDE.md` **맨 끝에** 절 하나(`## 내 해커톤 프로젝트`)를 더한다. 이미 있는 줄은 고치지 않는다. 10–15줄.
- 앱 이름 · 한 줄 · 사용자 · 화면(≤3) · 데이터(어디에 · 몇 줄 · 가상) · 저장(파일 / 브라우저 / DB) · 하지 않는 것
- 마지막 줄: "끝날 때마다 `npm run build` 통과 + SPEC의 확인 기준 3줄"
- 끝나면 보여 줄 것: 더한 줄 수 · 하지 않는 것 · `git diff --stat`.

## 3. 뼈대와 첫 배포

기능이 없어도 **운영 주소에서 열리는 뼈대**를 먼저 올린다.
- `SPEC.md`의 화면 목록대로 쪽을 만든다(3개 이하). 쪽마다 제목 · 한 줄 설명 · 빈 상태와 가상 예시 줄 3–5개.
- 홈(`app/page.tsx`)을 내 앱의 첫 화면으로 바꾼다. 스타터의 바이어 홈 내용은 지워도 된다(계획에 적는다). `DeployBadge`는 첫 화면 아래에 남긴다 — 운영 주소 확인용.
- `app/layout.tsx`: 앱 이름 · 내 쪽만 담은 `SiteNav` · 바닥 글 "(가상) 데이터 · 해커톤 시제품 · 결정은 사람이 합니다".
- 아직 안 되는 단추는 '곧 열려요'로 둔다. `components/`의 부품을 먼저 쓴다.
- `npm run build` 통과 → 커밋 · push(파일 목록 · 메시지 먼저) → Vercel이 다시 배포한다.
- 끝나면 보여 줄 것: 만든 쪽 주소 목록 · build 결과(쪽 표) · 커밋 한 줄.

## 4. 시나리오 하나씩

프롬프트가 고른 **시나리오 하나만** 만든다. Given–When–Then이 곧 완료 기준이다.
- 계획 3–7줄: 바꿀 파일 · 데이터 · 운영 주소에서 확인하는 법.
- 쓰기 동작이면 서버 액션(`'use server'`)으로 하고, 입력을 코드로 검사한다(빈칸 · 길이 · 숫자 범위 → 한국어 안내). 지우기보다 '취소' 상태를 먼저 생각한다. 저장 위치는 「5」의 결정대로.
- 브라우저 기능(마이크 · 카메라 · 알림 · 흔들기 · 소리)은 `'use client'` 부품 안에서, 단추를 누를 때 시작한다. 지원하지 않는 브라우저에서는 안내 한 줄을 보이고 앱은 그대로 돈다. 알림(Notification)은 PC 브라우저에서만 뜬다 — 휴대폰에서 보여 줄 장면이면 `.ics` 캘린더 내려받기를 먼저 권한다.
- `npm run build` 통과 → 커밋 · push → `SPEC.md`의 그 시나리오 옆에 `[됨]`.
- 끝나면 보여 줄 것(확인 방법 3줄): Given을 만드는 법 · When에 누를 곳 · Then에 보일 것 — 운영 주소 기준.

## 5. 데이터

- 기본은 **파일**: `data/`의 JSON(200줄 이하)을 `import`로 읽는다(쪽 · 서버에서). `data/buyers.json` · `fx_fallback.json` · `hackathon/sample_data/`의 CSV 셋(경비 30 · 방문객 20 · 비품 25)을 써도 된다.
- CSV는 `import`가 안 된다 — `scripts/csv-to-json.mjs`(새로 만든다 · 의존성 없음)로 한 번 JSON으로 바꿔 `data/`에 둔다. sample_data의 CSV는 UTF-8 BOM(엑셀용)이고 따옴표 · 칸 안 쉼표가 없다 — 첫 글자 BOM을 떼고 읽는다.
- 가상 데이터를 새로 만들 때는 손으로 쓰지 말고 `scripts/make-data.mjs`(새로 만든다 · 고정 시드)로 만들어 다시 만들 수 있게 한다. `data/README.md`에 파일 · 줄 수 · 만든 방법 한 줄.
- 저장이 필요할 때 — 고르는 법
  - 내 기기에서만 남으면 되는 것(내 체크리스트 · 내 기록) → **브라우저 저장**(`localStorage`, `'use client'` 부품에서만 — 수강생이 화면에서 입력한 값만 담고, `data/` 파일 · 비밀은 넣지 않는다). 화면에 "이 기기에만 저장됩니다" 한 줄.
  - 여러 사람이 같이 봐야 하는 것(예약 · 신청 · 투표 · 방문 등록) → **DB**(「6」).
  - 시연만 되면 되는 것 → 화면 안에서만(새로 고침하면 처음으로 — 화면에 한 줄로 알린다).
- 가상 표시: 화면 위나 바닥에 "모든 데이터는 가상" 한 줄, 사람 · 회사 이름 옆 `(가상)` 또는 `김○○`처럼 가린 이름. 전화번호는 `010-0000-0000` 꼴, 이메일은 `@….example`.

## 6. DB를 쓸 때

저장이 핵심일 때만. 5일차 DB는 쓰지 않는다(그 DB에 `db:push`하면 5일차 표가 지워질 수 있다).
- **사람이** 새 Supabase 프로젝트를 만든다 — 이름 `hack-T{조}-{번호}` · Region Seoul · 비밀번호 영문 + 숫자 16자 이상(기호 없음). 무료 2개 한도면 5일차 프로젝트를 Pause.
- `npm run env:init` → 사람이 Connect → ORMs → Prisma의 두 줄(`DATABASE_URL` 6543 · `DIRECT_URL` 5432)을 `.env`의 빈 `DATABASE_URL=""` · `DIRECT_URL=""` 자리에 붙여 넣는다(빈 두 줄은 지운다 — 같은 이름이 두 번 있으면 뒤의 줄이 쓰인다). AI는 `.env`를 열지 않는다. 확인은 `npm run doctor:db`.
- `prisma/schema.prisma`에 모델 1–2개(`id` · `createdAt` 포함). 표 만들기는 `npm run db:push`로만 — 데이터가 지워진다고 물으면 멈추고 사람에게 묻는다. 끝에 'RLS 켬 n/n'을 확인한다.
- 처음 데이터는 `prisma/seed.ts`(두 번 돌려도 같은 줄 수 — `skipDuplicates`나 `upsert`) → `npm run db:seed`.
- DB를 읽는 쪽은 `export const dynamic = "force-dynamic"`. DB는 `lib/db.ts`의 `db()`로만(고치지 않는다). 쓰기는 서버 액션 · 입력 검사 · `revalidatePath`, 화면은 `useActionState`로 '저장 중'.
- 배포: 사람이 Vercel Settings → Environment Variables에 `DATABASE_URL`을 넣고(값은 `.env` 6543 줄의 따옴표 안만 · `DIRECT_URL`은 넣지 않는다) **Redeploy**.
- 끝나면 보여 줄 것: 표 이름 · 줄 수 · 운영 주소에서 쓰고 새로 고침해도 남는지.

## 7. AI를 넣고 싶을 때

- **(a) 기본 — AI가 미리 만들어 두기(앱 안에는 키 없음).** `scripts/ai-batch.ts`(새로 만든다)가 `scripts/lib/ask-claude.ts`의 `askClaudeJson`으로 `data/`의 가상 데이터를 요약 · 분류 · 점수화해 `data/ai_<이름>.json`에 쓴다.
  - JSON 스키마를 정하고, 받은 값은 코드로 검사한다(허용 목록 밖이면 `확인 필요`).
  - `--dry-run`(AI를 부르지 않고 건수와 첫 프롬프트만) · `--limit N`. 이미 만든 건 건너뛴다(다시 돌려도 AI 호출 0). 동시에 3건까지(같은 파일의 `mapLimit`).
  - 실행은 사람: `npx tsx scripts/ai-batch.ts`. 앱은 그 JSON을 `import`하고, 결과 옆에 "AI가 미리 만든 결과 · 사람 확인 전".
- **(b) 선택 — 앱 안에서 AI 부르기(키가 필요하다 · 먼저 묻는다).** Vercel AI Gateway나 수강생 본인의 API 키를 쓴다. 패키지가 필요하면 이름 · 고정 버전을 먼저 묻는다(예: `ai@7.0.143 --save-exact`).
  - 부르는 곳은 서버(route handler · 서버 액션)뿐이다. 키는 `.env`와 Vercel 환경 변수에만 두고, `NEXT_PUBLIC_`에는 넣지 않는다.
  - 승인 코드(PIN)나 횟수 제한을 붙이고, 실패하면 정해 둔 대체 글을 보인다. 결과 옆에는 "AI 초안 — 사람 확인 전"을 붙인다.
  - 쓰기 전에 그 서비스 콘솔에서 사용 한도부터 정하게 안내한다. 결제 화면이 나오면 멈추고 알린다.
- 어느 길이든 결정 · 발송은 사람이 한다. 끝나면 보여 줄 것: 만든 파일 · 실행 명령(사람이 칠 것) · 화면의 'AI' 표시 자리.

## 8. 다듬기 · 자유 퀘스트

### 8-1 다듬기

- `guide/design_rules.md` 그대로. **기능 · 숫자 · 데이터는 바꾸지 않는다** — 모양만.
- 첫 화면 맨 위에서 발표 장면(시나리오 1)이 보이게: 앱 이름 · 한 줄 · 핵심 숫자나 단추 하나.
- 390px에서 가로 스크롤 없음 · 단추 44px · 빈 상태와 오류 문구는 한국어 · '(가상)' 표시 · 'AI 티'(이모지 · 보라 그라데이션 · 무지개 막대 · 뜻 없는 아이콘) 없음.
- 수강생이 적은 '아쉬운 곳'부터 고친다. AI는 화면을 직접 보지 못할 수 있다 — 390px 확인은 사람에게 부탁한다.
- 끝나면 보여 줄 것: 고친 곳 · 390px에서 볼 곳 · build 결과.

### 8-2 자유 퀘스트 — '와!' 하나

수강생이 '하고 싶은 것 한 줄'을 준다(몰라도 된다).
1. 지금 앱 · `SPEC.md` · 아이디어 카드 가운데 있는 것을 읽고(아침이면 `hackathon/idea_seeds.md`도), **재미있는 방향 3개**를 먼저 제안한다 — 각각 '와!' 한 줄 · 걸리는 시간 · 키나 패키지가 필요한지 · 휴대폰에서도 되는지. 하나 이상은 키 없이 되는 감각(듣기 · 말하기 · 카메라 · 알림 · 인쇄 · 공유)이나 게임으로.
2. 수강생이 고르거나 고치면 계획 3줄을 보이고, 승인받은 뒤 만든다.
3. 이미 되는 시나리오 · 숫자 · '하지 않을 것'은 그대로 둔다. MVP 규칙도 그대로다.
4. 새 패키지 · 키 · 바깥 발송이 필요하면 먼저 묻는다. 데이터는 가상만.
5. 마이크 · 카메라 · 위치는 브라우저의 허락 창을 거치고, 받은 소리 · 사진은 저장하거나 서버로 보내지 않는다(필요하면 먼저 묻는다). 브라우저 받아쓰기는 소리가 브라우저 회사 서버를 거칠 수 있으니 화면에 한 줄로 알린다.
6. `npm run build` 통과 → 확인할 것 3줄(어디를 누르면 · 무엇이 보이면 성공 · 휴대폰에서 볼 것).
'아무거나'면: 지금 앱으로 할 수 있는 **가장 놀라운 것 3가지**를 같은 모양으로 제안한다.

## 10. 게시 전 점검

- `npm run build` → `npm run doctor:secrets`를 돌리고 결과를 표(항목 · 결과 · 고칠 곳)로 보여 준다.
- 더 볼 것: `git ls-files`에 `.env` 없음 · `app/` `data/` `README.md` `SPEC.md` `DEMO.md`에 실명 · 실제 회사 · 실제 이메일 · 전화번호 없음 · 화면에 '(가상)' 표시 · 운영 주소가 `-<영문숫자>-<범위>.vercel.app` 꼴(미리보기 주소)이 아님.
- FAIL이면 고치는 법만 먼저 제안하고, 승인받은 뒤 고친다. 키 · 비밀번호가 커밋됐으면 지워도 이력에 남는다 — 그 키부터 폐기 · 재발급하도록 알리고, `push --force`는 하지 않는다.
- 끝나면 보여 줄 것: FAIL 0 · 운영 주소 · 마지막 커밋 한 줄.

## 11. 막힐 때

**고치기 전에 원인부터.** 오류 끝 10줄을 받으면 원인 후보 3개와 각각의 확인 방법만 알려 준다(아직 고치지 않는다).

| 증상 | 흔한 원인 | 확인 |
|---|---|---|
| `npm run build` 타입 오류 | 없는 값 · 틀린 모양의 props | 오류 줄의 파일 · 줄 번호 |
| 내 PC는 되는데 Vercel만 실패 | 파일 이름 대소문자 · 커밋 안 한 파일 | Vercel 빌드 로그 · `git status` |
| 운영 주소에서 500 | 환경 변수 없음 · Redeploy 안 함 · 값에 따옴표 | Vercel Logs · Settings → Environment Variables |
| 링크가 Vercel 로그인을 묻는다 | 미리보기 주소를 공유함 | Domains의 운영 주소 |
| DB 연결 오류 | `.env` 줄 · 비밀번호 · 풀러 포트 | `npm run doctor:db` |
| `'use client'`에서 데이터 · 비밀 import | 서버 전용 코드가 브라우저로 감 | 그 파일 맨 위 · import 줄 |
| Hydration 오류 | 화면에서 `Date` · `Math.random` | 서버에서 계산해 props로 |

## 12. 채팅 경로

Claude Code를 못 쓰는 날에도 발표는 한다.
